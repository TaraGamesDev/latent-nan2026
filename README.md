# CADENCE

**레벨을 만들지 않습니다. 매 순간을 설계합니다.**

7×7 격자의 화살표 퍼즐. 화살표를 누르면 그 방향으로 미끄러지고, 판 밖으로 나가면 득점합니다.
도중에 막히면 **거기 멈춰서** 다른 화살표들의 길을 바꿉니다 — 그래서 순서가 전부입니다.

그리고 **매 탭마다** AI 디렉터가 당신을 다시 평가하고, 다음 순간을 설계합니다.

> NHN GAME × AI 해커톤 (NAN 2026) 사전과제 제출작

---

## 무엇이 AI인가

대부분의 "AI로 만든 게임"은 AI를 **개발 도구**로 씁니다. 이 프로젝트에서 AI는 **제품 안에서 돌아가는 시스템**입니다.

```
매 배치 → 텔레메트리
   ↓   regret = value(솔버의 최선수) − value(플레이어의 수)      ← 수순당 스킬 신호
[스킬 추정기]   θ, {계획성 · 효율 · 템포}  +  {좌절도 · 지루함}
   ↓
[AI 디렉터]    플로우 채널 목표 + 강도 램프 → 제약조건 발행
               (탈출 체인 선호 깊이 / 스폰 압력 / 중앙 편향 / 방향 다양성)
   ↓
[생성기 + 솔버] 후보 스폰 배치 40개 샘플링 → 제약 대비 채점 → 승자 선택
               ★ 불변식: 스폰 직후 반드시 최소 1수는 움직일 수 있다
   ↓
[글래스박스 패널]  위 전부를 화면에 그대로 노출
```

**런타임은 전부 결정론적입니다.** 네트워크도, API 키도, 계정도 필요 없습니다.
LLM은 오프라인 정책 저작·튜닝 단계에서만 쓰였고, 그 산출물은 `src/ai/policy.ts`에 구워져 있습니다.

## 핵심 아이디어 세 가지

### 1. 수순당 후회(regret)로 실력을 잰다

레벨 클리어 여부는 몇 분에 한 번 오고, 그 레벨이 마침 쉬웠는지에 오염됩니다.
대신 **모든 탭을, 그 탭이 이루어진 바로 그 국면에서** 솔버의 최선수와 비교합니다.

```
regret = (최선수의 가치 − 플레이어가 고른 수의 가치) / (그 국면에서의 선택지 편차)
```

선택지가 전부 동등한 국면은 정보량 0으로 처리되어 추정을 흔들지 않습니다.
`src/ai/skill.ts`

### 2. 의도와 시공을 분리한다

디렉터는 화살표를 직접 놓지 않습니다. **"지금 이 순간이 어떻게 느껴져야 하는가"**를 제약조건으로 발행할 뿐입니다.
실제 배치는 생성기가 샘플링하고 솔버가 검증합니다.

플레이어를 평가하는 쪽은 heuristic이어도 되지만, **보드를 건드리는 쪽은 틀리면 안 되기 때문**입니다.
`src/ai/director.ts`

### 3. 약속은 작게, 대신 반드시 지킨다

초기 버전은 "탈출 4수 보장"을 약속했습니다. 벤치를 돌려보니 **1~2개 스폰으로는 구성 불가능한 약속**이었고, 15,829회 위반했습니다.
그래서 선호로 강등하고, 대신 증명 가능한 것만 남겼습니다:

> **스폰 직후 항상 최소 1수는 움직일 수 있다.**

모든 후보에 대해 정확히 검사하며, 어떤 배치도 이걸 통과하지 못하면 스폰 수를 줄입니다. 불변식을 깨지는 않습니다.
플레이어는 **자기 선택으로는 질 수 있어도, 디렉터 때문에 지지는 않습니다.**

## 직접 확인해 보기

게임 안 **AI 패널** (우상단 버튼 또는 `D` 키)에서 전부 볼 수 있습니다:

- 지금 이 순간 시스템이 당신을 어떻게 추정하고 있는지 (θ와 세 하위 지표)
- 숙련도 · 목표 난이도 · 실제 난이도가 겹쳐 그려지는 **플로우 채널 그래프**
- 이번 스폰을 그렇게 결정한 이유 (한국어 문장)
- **검토된 후보들과 채택되지 않은 대안들**, 각각의 난이도·탈출 체인·가동 수·점수
- 불변식 검증 결과와 기각된 후보 수
- 솔버가 증명한 탈출 체인이 보드 위에 번호로 표시됩니다

## 개발

```bash
npm install
npm run dev     # localhost:5173
npm run build   # docs/ 로 빌드 (GitHub Pages)
npm run bench   # 헤드리스 엔진 검증
```

### `npm run bench`

봇 페르소나(novice / casual / expert)로 전체 게임을 **실제 `tap()` 경로**를 통해 돌립니다.
심사자가 플레이하는 바로 그 코드에서 나온 수치입니다.

세 가지를 보고만 하는 게 아니라 **단언**합니다:

1. 불변식이 모든 런의 모든 탭에서 유지되는가
2. 모든 런이 종료되는가 — 잘하는 플레이어가 불사신이 되면 안 됩니다
3. θ가 세 페르소나를 마땅한 순서로 정렬하는가

## 구조

| 경로 | 역할 |
|---|---|
| `src/core/grid.ts` | 보드 상태와 이동 규칙 |
| `src/core/rng.ts` | 시드 기반 PRNG — 모든 런은 시드로 재현됩니다 |
| `src/ai/solver.ts` | 국면 평가, 탈출 폐포, 체인 탐색 |
| `src/ai/skill.ts` | 수순당 후회 → 숙련도 추정 · 감정 상태 |
| `src/ai/director.ts` | 제약 발행 + 제약 기반 스폰 생성 |
| `src/ai/policy.ts` | 오프라인 튜닝 대상 상수 |
| `src/ai/bots.ts` | 봇 페르소나 (콜드스타트 해결책) |
| `src/game/game.ts` | 한 탭 = 한 턴 |
| `src/ui/` | 캔버스 렌더러 · 디렉터 패널 |
| `src/tools/` | 벤치 · 튜너 · 단일 런 추적기 |
