# LATENT

**덮인 타일은 아직 정해져 있지 않습니다.**

층층이 쌓인 타일을 걷어내 같은 무늬 3개를 모으는 퍼즐. 트레이는 7칸,
가득 차면 끝입니다. 여기까지는 익숙한 형태입니다.

다른 점은 하나뿐입니다 — **레벨이 미리 존재하지 않습니다.**
덮여 있는 타일은 무늬가 없습니다. 숨겨진 게 아니라 **아직 결정되지 않은** 것이고,
드러나는 순간 AI가 **당신의 그 시점 상황을 보고** 무늬를 정합니다.

> NHN GAME × AI 해커톤 (NAN 2026) 사전과제 제출작

## 왜 이게 중요한가

캐주얼 퍼즐의 원가는 **레벨 뱅크**입니다. 수천 개의 레벨을 사람이 만들고,
그보다 더 비싼 일 — **만든 레벨이 풀리는지 검증** — 을 합니다.

레벨을 미리 만들지 않으면 **그 검증 단계가 통째로 사라집니다.**

```
매 타일이 드러날 때마다
   │
   ├─▶ [스킬 추정기]  src/ai/skill.ts
   │     regret = value(솔버의 최선수) − value(플레이어가 고른 수)
   │     → θ(숙련도), {계획성 · 정돈 · 템포}, {좌절도 · 지루함}
   │
   ├─▶ [배정기]       src/ai/assigner.ts        ← 의도
   │     θ + 감정 + 레벨 진행 램프 → 목표 난이도
   │     트레이 위험도가 높으면 난이도와 무관하게 구제
   │
   ├─▶ [완결성 검사]  같은 파일                   ← 시공
   │     ★ 미결정 타일 수 ≥ 3의 배수를 맞추는 데 필요한 타일 수
   │     이 부등식만 지키면 클리어 가능성은 구성상 보장됩니다
   │
   └─▶ [글래스박스 패널] src/ui/panel.ts
         위 전부를 화면에 그대로 노출
```

**런타임은 전부 결정론적입니다.** 네트워크도, API 키도, 계정도 필요 없습니다.

## 핵심 설계 세 가지

### 1. 수순당 후회(regret)로 실력을 잰다

"레벨을 클리어했는가"는 몇 분에 한 번 오고, 그 레벨이 마침 쉬웠는지에 오염됩니다.
대신 **모든 탭을, 그 탭이 이루어진 바로 그 국면에서** 솔버의 최선수와 비교합니다.
국면이 통제되어 있으므로 "쉬워서 잘한 것"과 "실제로 잘 둔 것"이 섞이지 않습니다.

### 2. 의도와 시공을 분리한다

배정기는 *"지금 이 순간이 어떻게 느껴져야 하는가"*만 정합니다.
실제로 무늬를 쓰기 전에 **완결성 부등식**이 별도로 검사합니다.
플레이어를 평가하는 쪽은 틀려도 되지만, **타일을 쓰는 쪽은 틀리면 안 되기 때문**입니다.

### 3. 약속은 작게, 대신 반드시 지킨다

> **이 레벨은 끝까지 클리어 가능합니다.**

배정 시점에 `미결정 타일 ≥ 필요 타일`만 지키면 성립합니다. 사후 검증이 없습니다.
다만 **질 수는 있습니다** — 서로 다른 무늬를 무턱대고 집으면 트레이가 찹니다.
계산해 보면 절대 지지 않게 만드는 건 불가능하고, 그래서도 안 됩니다:
보이는 무늬가 k종이면 최악의 경우 2k장까지 쌓이므로 k가 4만 되어도 7칸이 찹니다.

## 직접 확인해 보기

**AI 패널** (우상단 버튼 또는 `D` 키):

- 지금 시스템이 당신을 어떻게 추정하는지 (θ와 세 하위 지표, 좌절도/지루함)
- 숙련도 · 목표 난이도 · 실제 난이도가 겹쳐 그려지는 **플로우 채널**
- **방금 쓴 타일의 근거** (한국어 문장)
- **검토된 후보 무늬들과 채택되지 않은 것들**, 완결성 판정 포함
- 불변식 검증: 미결정 타일 ≥ 필요 타일
- 패널이 열려 있으면 **AI가 방금 결정한 타일이 보드 위에 표시**됩니다

## 개발

```bash
npm install
npm run dev     # localhost:5173
npm run build   # docs/ 로 빌드 (GitHub Pages)
npm run bench   # 헤드리스 엔진 검증
```

`npm run bench`는 봇 페르소나로 전체 게임을 **실제 `tap()` 경로**로 돌리고
세 가지를 **단언**합니다: 완결성 불변식 유지 / 약한 플레이어는 반드시 패배 /
θ가 페르소나를 마땅한 순서로 정렬.

## 이 규칙을 고른 근거

세 가지 후보를 **같은 축(정확한 검증 비용)** 으로 재고 골랐습니다. `src/probe/`:

| 후보 | 검증 처리량 | 정확성 |
|---|---|---|
| A · STAMP (GF(2) 토글) | 85,228 레벨/초 | 완전 정확 (풀림·최소수·해 개수) |
| B · MAGNET (당기기) | 26 레벨/초 | 불완전 — 깊이 제한, 미해결은 *미지* |
| **C · 타일 + 지연 결정** | **470,000 결정/초** | 검증 단계 자체가 없음 |

B가 A보다 3,300배 느린 이유가 이 프로젝트의 논지입니다. 소코반이
PSPACE-complete라서 레벨 자동 생성이 *논문 주제*인 것과 같은 이유입니다 —
**비싼 건 생성이 아니라 검증입니다.**
